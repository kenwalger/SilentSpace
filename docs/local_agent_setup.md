# Local Agent Setup

This guide covers running Hermes or any other local agent runtime against the
SilentSpace Guardian pipeline. Everything here is local-first: no cloud accounts,
no OAuth, no subscriptions required.

---

## Prerequisites

Before wiring an agent, the base system must work:

```bash
# Verify the full pipeline
bash scripts/verify_demo.sh

# Confirm hermes_meeting_tool.py works
python python/hermes_meeting_tool.py meetings/weekly_alignment_sync.json
```

If either fails, resolve it before adding agent complexity.

---

## GnuCOBOL Installation

The COBOL entropy engine must be compiled before any agent can use it.
`audit_meeting.py` compiles it automatically on first run if `cobc` is available.

### macOS

```bash
brew install gnu-cobol
```

### Ubuntu / Debian / WSL

```bash
sudo apt update && sudo apt install gnucobol
```

### Windows (native)

GnuCOBOL is not available natively on Windows without WSL. The Python wrapper
detects WSL automatically and compiles through it. See
[docs/windows-wsl-setup.md](windows-wsl-setup.md) for WSL2 setup.

### Verify

```bash
cobc --version
python python/hermes_meeting_tool.py meetings/weekly_alignment_sync.json
```

## Provider Options

SilentSpace Guardian does not mandate a specific LLM provider. The tool boundary
(`python/hermes_meeting_tool.py`) is provider-agnostic. Choose based on what
you have available locally.

### Ollama (local, no API key)

Ollama runs models locally. No internet required after initial model download.

```bash
# Install Ollama
# macOS: brew install ollama
# Linux: curl -fsSL https://ollama.com/install.sh | sh

# Pull a model
ollama pull mistral
ollama pull llama3

# Start Ollama server (if not already running)
ollama serve
```

Point your agent runtime at `http://localhost:11434` with provider `ollama`.

Recommended models for audit tasks: `mistral`, `llama3`, `qwen2.5`.

### OpenRouter

OpenRouter provides access to many models via a single API key. Useful for
testing different models without managing local resources.

```bash
# Set in .env or environment
OPENROUTER_API_KEY=sk-or-...
```

Use `https://openrouter.ai/api/v1` as the base URL with OpenAI-compatible
SDKs. Recommended models: `anthropic/claude-3-haiku`, `mistralai/mistral-7b-instruct`.

### Anthropic API

For Claude models directly:

```bash
ANTHROPIC_API_KEY=sk-ant-...
```

### Setting Environment Variables

Copy `example.env` to `.env` and populate:

```bash
cp example.env .env
```

`.env` is gitignored. Never commit API keys.

## Wiring the Tool Boundary

### In-process Python (cleanest)

```python
import sys
sys.path.insert(0, "python")
from audit_meeting import audit_meeting_data

# Define this as a tool in your agent framework
def audit_meeting_tool(meeting: dict) -> dict:
    return audit_meeting_data(meeting)
```

Register `audit_meeting_tool` as a callable tool in your agent runtime.

### Out-of-process subprocess

If your agent runtime executes shell commands:

```python
import subprocess, json

def call_hermes_tool(meeting_json: str) -> dict:
    result = subprocess.run(
        ["python", "python/hermes_meeting_tool.py", "--stdin"],
        input=meeting_json,
        capture_output=True,
        text=True,
    )
    if result.returncode != 0:
        raise RuntimeError(result.stderr.strip())
    return json.loads(result.stdout)
```

## SOUL.md as the Behavior Contract

Regardless of provider or runtime, the agent must conform to
[SOUL.md](../SOUL.md). The key directives for agent configuration:

- The system prompt should reference SOUL.md or reproduce its directives
- The agent should not soften, reframe, or apologize for findings from the scoring pipeline
- The agent should produce a score or classification before any prose
- Recommendations come from the fixed pool in `classify.py` — they are not generated by the LLM

A minimal system prompt excerpt:

```
You are the SilentSpace Guardian. You are not an assistant. You are an auditor.
Classify before commenting. Score before summarizing. Preserve evidence.
Recommendations must reduce organizational entropy.
Never manufacture optimism to soften findings.
```

## Verifying the Setup

```bash
# Hermes tool: file input
python python/hermes_meeting_tool.py meetings/weekly_alignment_sync.json

# Hermes tool: stdin
cat meetings/weekly_alignment_sync.json | python python/hermes_meeting_tool.py --stdin

# Hermes tool: with report
python python/hermes_meeting_tool.py meetings/weekly_alignment_sync.json --write-report

# Check generated report
cat reports/weekly_alignment_sync_report.md
```

All commands should exit 0 and produce valid JSON on stdout.
